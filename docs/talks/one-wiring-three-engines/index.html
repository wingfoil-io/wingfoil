How making node semantics an associated function
bought us an interpreter, a compiler and a JIT-shaped middle — from one copy of the code.

The problem shape

A graph of calculations over event streams

  • Nodes are stateful and mostly small.
  • Events arrive, and a subset of the graph has to react.
  • You want to replay it over history, then run the same wiring live.
  • The overhead budget is nanoseconds per node, not microseconds.

Who has this problem

Electronic trading. Real-time decisioning and risk. Streaming ML features. Anywhere the answer has to be right and the deadline is measured in microseconds.

Why it is interesting

It is the one workload where the framework's overhead, not your arithmetic, is the thing you are paying for.

Don't dwell. 90 seconds. The audience is Rust engineers — they recognise the shape immediately. The point of this slide is only to establish that per-node overhead is the budget, because that is what makes the rest of the talk necessary.

The hook

127 levels deep. 2127 distinct paths. One tick.

let mut source = g.constant(1_u128);
for _ in 1..128 {
    source = source.join(&source, |a, b| a + b);   // branch and recombine
}
1 ticks processed in 12.953µs
value 170141183460469231731687303715884105728

That value is 2127 — the correct answer, which is also exactly the number of source→sink paths a framework that propagates one path at a time would have to walk.

THIS is the slide that wakes the room up. Land it slowly. "Every one of those 2^127 paths is a real path through the graph. A reactive library that pushes along one path at a time has to walk all of them. We visit 128 nodes." Pause. Then next slide explains why.

Why

Visit each node once per tick, in topological order

A node runs after everything it reads, exactly once, no matter how many upstream paths lead to it.

Libraries that propagate along one path at a time re-visit shared nodes once per path — so on branch-and-recombine their cost doubles every level while ours stays flat.

Measured slopes: 2.01× and 1.94× per level. Ours: flat.

Least squares over ten depths gives ≈ 68 ns + 22 ns × depth interpreted — one more node per level, while the path count runs to 1024.

Log scale. At depth 10: ~39× faster than rxrust, ~134× than tokio async streams. The flatness is the claim, not the multiplier — and both comparisons are written down with the caveats that cut against us.

Be scrupulous here — a Rust audience will respect the honesty and punish the lack of it. Say out loud: the rxrust figure is HALVED from the raw ratio because its benchmark emits twice per sample; the tokio target is recursive Box::pin over an immediately-ready leaf, which is an honest depiction of per-path propagation but not the best an async implementation could do. The claim is the SLOPE, not the multiplier.

The wall we hit

We built an ahead-of-time code generator. It failed three ways.

Ran the wiring from build.rs, walked the graph, emitted a straight-line runner with node state in locals. Sound plan.

1 It had to re-implement every node. Semantics lived inside node objects, welded to RefCell fields and stored upstream handles. Generated code could not call a node's cycle — there was nothing callable that didn't drag the storage model along. So the emitter carried its own copy, as strings. Two implementations of map, two of filter, two of fold — one that runs, one that gets emitted, and nothing keeping them in step.
2 Types and closures were already gone. Wiring erased them. Types came back from the traversal as name strings, so the emitter reverse-engineered them by parsing. Closures could not be recovered at all — there is no way to get |x| x * 10 back out of a Box<dyn Fn>. The workaround was making the user re-state every closure in a side table.
3 Scheduling was inferred from names. Nothing on a node declared "I schedule my own callbacks" or "I am fed from another thread", so the engine drove nodes off name-based allowlists. A user-defined node that needed to self-schedule had no way to say so.
Take your time — this is the argumentative core. Three walls, ~30s each. Wall 2 usually gets a laugh: "a human re-typing the closure that already exists ten lines up, with no compiler check that the two agree." Then: we deleted that generator.

The diagnosis

The problem was not the code generator.
It was that node semantics were not separately callable.

All three walls trace back to one fusion: a node was its computation, and its storage, and its input plumbing — one object, three concerns.

No amount of cleverness in the emitter fixes a design where there is nothing to emit a call to.

So we deleted the generator, and rewrote the engine around the thing that had been missing.

Slow down on the punch line. This is the sentence the whole talk is organised around. Let it sit for a beat before advancing.

The one decision everything follows from

Semantics became an associated function

trait Op {
    type Cfg;              // construction-time config; closures live here
    type State;            // engine-owned mutable state
    type In<'a>;           // typed inputs, passed in per cycle
    type Out;              // the produced value
    const ACTIVATION: Activation;

    fn cycle(cfg: &mut Self::Cfg, state: &mut Self::State,
             input: Self::In<'_>, ctx: &mut Ctx<'_>) -> Result<Tick<Self::Out>>;
}

Read what is absent. Nothing here says how state is stored, where inputs come from, or who calls it.

Not a method on an instantiated object — an associated function over explicit arguments. Every one of those four associated types is a hole the engine fills, and the engine gets to choose HOW it fills them. Don't rush to the payoff — make them look at the absence first.

The payoff

The three walls fall out at once

1 There is now something callable to emit calls to. One copy of the semantics, reachable from any machinery.
2 Types and closures are ordinary generic parameters, so they survive into generated code by construction. Nothing to reverse-engineer; nothing to re-state.
3 const ACTIVATION states scheduling behaviour where a machine can read it. NONE / SCHEDULES / THREADED / ALWAYS — a const, so the interpreter reads it at wiring time and the compiled emission folds it into a dispatch condition after monomorphization.
Fast — 60 seconds. The audience has already been handed the walls; this is just closing the loop. The satisfying bit is that nobody designed three fixes: one change fixed three things, which is usually the sign the change was at the right level.

What it buys

Three execution strategies, one copy of the semantics

StrategyWho owns stateDispatch
Interpretedthe builder's slotsone dyn call per node
Compiledlocal variables in a generated fnmonomorphized, inlinable
Nested islandlocals inside one composite nodemonomorphized inside, one dyn call outside

Not three implementations kept in sync by discipline and tests. One implementation — which is why they cannot drift.

If you ever find yourself writing a second copy of what a node does, that is the invariant breaking. It is the only invariant in the codebase treated as non-negotiable.

The island is the interesting one for a Rust crowd: a compiled sub-graph mounted as ONE node of an interpreted graph. Hot core monomorphized, edges stay open for threaded sources, feedback, bursts. You get the compiled tier without giving up the open world.

The front door

You write the wiring once, in plain Rust

wingfoil::nitro! {
    fn odds_evens(g: &GraphBuilder) -> Stream<String> {
        let count    = g.ticker(PERIOD).count();
        let is_even  = count.map(|i| i.is_multiple_of(2));
        let is_odd   = is_even.map(|b| !b);
        let odd_str  = count.filter(&is_odd).map(|i| format!("{i} is odd"));
        let even_str = count.filter(&is_even).map(|i| format!("{i} is even"));
        let labelled = odd_str.merge(&even_str);
        labelled
    }
}

Out comes odds_evens::interpreted(), odds_evens::compiled() and odds_evens::nested() — from the same tokens.

The wiring function stays valid, reviewable Rust either way. That property was deliberately never traded away: count is read three times, so it is a shared apex node — the macro derives a real DAG, not a chain.

The constraint worth stating: wiring must be straight-line. Values and per-element logic can be as procedural as you like — the TOPOLOGY cannot depend on runtime values, because compiled() monomorphizes one local per node and the node list has to be complete after parsing. If asked about loops: .map_n / .fan with a literal count.

…and this is what it becomes

One function. One local per node. No dyn.

let mut __k = Kernel::new(run_mode, run_for);

let mut __cfg_wf_anon_1   = PERIOD;
let mut __state_wf_anon_1 = __wf_op_ticker_seed_state(&__cfg_wf_anon_1);
let mut __v_wf_anon_1     = __wf_op_ticker_seed_value(&__cfg_wf_anon_1);
// … one cfg / state / value local per node, 11 nodes …

let mut __dirty = [false; 11usize];
while __k.begin_cycle(&mut __dirty) {
    let __t_wf_anon_1 = /* activation */ && {
        let mut __ctx = Ctx::new(&mut __k, 0usize);
        match __wf_op_ticker_cycle(&mut __cfg_wf_anon_1,
                                   &mut __state_wf_anon_1, (), &mut __ctx)
              .context("node 0 (wf_anon_1: ticker) cycle")? {
            Tick::Value(__val)  => { __v_wf_anon_1 = __val; true  }
            Tick::Silent(__val) => { __v_wf_anon_1 = __val; false }
            Tick::Quiet         => false,
        }
    };
    // … 10 more, emitted in topological order …
}

Point at the call: that is the SAME cycle function the interpreter calls. Not a re-implementation — a call. That is wall 1 being dead. Point at `.context("node 0 (wf_anon_1: ticker) cycle")` — error context uses the binding name the USER wrote, baked in as a &'static str at expansion time, so it costs nothing until something fails. The full expansion is committed in the repo so nobody has to trust me.

Both engines are in the binary

$ WINGFOIL_TIER=interpreted dual_mode
0.000_000 odds/evens "1 is odd"
0.010_000 odds/evens "2 is even"
0.020_000 odds/evens "3 is odd"
   …
ran 10 cycles on the interpreted tier
$ WINGFOIL_TIER=compiled dual_mode
0.000_000 odds/evens "1 is odd"
0.010_000 odds/evens "2 is even"
0.020_000 odds/evens "3 is odd"
   …

Same binary. Same output. Different engine.

Develop interpreted — it honours the tracing span features and supports dynamic graph surgery, neither of which the monomorphized tiers have. Deploy compiled. Tier::default() falls back to the build profile, so the usual workflow needs no call-site change at all.

That the tiers AGREE is not a hope — tests/macro_parity.rs runs this same diamond through all three engines and pins the outputs equal. That test is the structural form of the invariant: the property stays true rather than merely intended.

Three decisions that bite

Contract questions, settled early and on purpose

Tick has three states, not two

enum Tick<T> { Value(T), Silent(T), Quiet }

Value updates the slot and ticks downstream. Quiet does neither. Silent updates the value without ticking — which is exactly what delay needs, and why a "did it fire?" bool is not enough.

Bursts, never latest-wins

Same-instant values ride one Burst<T> and are delivered atomically. A source that coalesces them is a bug — the strictly-monotonic clock means a split same-time group cannot be reassembled.

Two clocks, and the engine owns the snap

time() is engine time — source-driven, pure logic under replay, consulting no clock at all. The only one business logic may use.

wall_time() is the cycle's wall-clock snap, for latency stamping. Taken lazily, on first read, cached in a Cell — so a cycle in which nothing stamps reads the clock zero times.

Which matters, because that read is ~24 ns and almost nothing wires a stamp.

Lesson worth naming out loud: decide contract questions in BLAST-RADIUS order. Fallibility came before everything because it touched every op. Tick::Silent was settled as a contract question rather than discovered while porting `delay`. Deciding either one late means retrofitting every emitter. This is the trim valve — cut to 30s if behind.

The outcome we most doubted

Wiring is open. Stream is closed.

Combinators are extension traits, never inherent methods — so a downstream crate adds vocabulary that feels native without this crate knowing about it. Two public primitives: GraphBuilder::source and Stream::wire.

#[op(build = my_thing)]          // on your Op impl, in your crate
impl Op for MyThing { … }        // → the interpreted builder method
                                 // → the nitro! forwarders compiled emission dispatches through

A user-defined op gets interpreted and fully-compiled coverage, within 2.4% of a built-in — with no edit to the macro crate and no table to register in.

There is no per-op table in the macro. Built-in and user ops take the identical path. If you are editing a match arm to add an op, you are on the wrong road.

"That was the property we most doubted was achievable, and it is the one that most changes what the library is for." A library where third-party ops are second-class is a library you eventually fork. This one you extend.

Three languages, one engine

Rust is the engine. Python gets the same graph model and combinators in the wheel, nodes written in Python, results out as a pandas frame. TypeScript is a browser client decoding the wire format with the server's own code compiled to wasm.

Per-hop latency tracing

Wall-clock stamps per stage, aggregating into one report — across shared memory and across the wire. Browser → venue → back, with every hop attributed.

Backtest, then live

Swap RunMode. Same wiring. Determinism comes from engine time being source-driven, so a replay consults no clock at all.

What we don't claim

No trading domain model. Adapter breadth behind csp and Nautilus. Youngest in its field. No wire-to-trade number until there's a kernel-bypass ingress to measure.

If you are about to do this to your own codebase

Three things we'd tell you

1 Decide the contract questions first, in blast-radius order. Fallibility came before everything because it touched every op. Deciding it late means retrofitting every emitter.
2 Point the dependency edge at the new thing. The old tree depended on the new one, not the reverse — so the shared core was already on the right side when the cutover came, and the last step was a deletion rather than an archaeological dig.
3 Make the invariant structural, not aspirational. "Keep the interpreted and compiled paths in sync" is a promise that decays. "There is exactly one copy of the semantics, and the second copy is a compile error" is a property.

The entire rewrite is one long argument for preferring the second kind.
