# Execution layer examples: from hand-driven calls to graphs

**Status:** plan, not started. Scope is `examples/adapters/execution/` only;
the unit tests stay as they are.

## The problem

All eight execution examples are off-graph. Not one constructs a
`GraphBuilder`; each holds an `Oms`, a `Book`, a `Reconciler` or a `Switch`
in `main`, advances a hand-rolled `at(ms)` clock in a `for` loop, and calls
`diff` / `apply` / `reconcile` / `record` by hand. That is the shape
`execution/CLAUDE.md` says a caller must not use ("a caller must not hold an
`Oms` in a `RefCell` and call it by hand from a graph … that is how every
caller came to re-derive the order"), so the examples teach the wrong thing
to the one audience that copies them. None of their wiring could be pointed
at a live venue, which the examples rule in the root `CLAUDE.md` calls the
anti-pattern. And they read like unit tests: a sequence of asserts with
`println!` in place of `assert_eq!`.

The graph API to do it right already exists: `OmsOps`, `AlgoOps` and
`FixOps` for the three stateful nodes; `testing::SimVenue` as a `Venue`
behind one `GraphBuilder::feedback` cut; `ceiling::Capped` wrapping any
venue; and `StreamOps::fold` for the three pure types that have no node of
their own (`Book`, `Reconciler`, `Switch` are all `Clone`, which is all
`fold` asks). `tests/execution_fix_venue.rs:449-483` (`closed_loop`) shows
the loop wired.

## The rule

> **Every execution example wires a graph and runs it under
> `RunMode::HistoricalFrom`, printing as the run goes.** The one exception
> is an example whose subject is vocabulary rather than behaviour, and its
> README says so.

It goes into `execution/CLAUDE.md` under *Tests* alongside the existing
"each with a README whose output is real".

## What each example becomes

Target names do not change; directory layout and the `adapters/` README
house style stay as they are. Every README's output is regenerated by
running the example, and stays stable because every run is historical.
Inputs that today are hand-stepped in a loop become replayed rows
(`g.replay_results(..)` at engine instants), the way `closed_loop` does it.

| Example | Today | Becomes |
|---|---|---|
| `oms_quote` | `Oms::diff` by hand, nine calls | A replayed decision stream into `OmsOps`; `SimVenue` behind the cut answers the requests; `print()` on requests and reports. Shows what the docs promise: one in flight per slot, the amend on a moved touch, withdrawal by decision and by age, the budget deferring |
| `message_ratio` | hand-driven | Same loop with `Config::ratio`; the held amend is visible as the instant it goes out |
| `replace_chain` | hand-driven `ReplaceChain` | `FixOps` on the graph in front of `SimVenue`, the renamed order and the fill on it printed as reports |
| `exchange_day` | hand-driven | A replayed `TradingState` stream driving `OmsOps` through the session: open, halt, close expiring day orders, re-open re-quoting |
| `position_book` | `Book::apply` by hand | `fills.fold(Book::new(measure), \|book, burst\| book.apply(burst))`, with a marks stream joined to print `pnl` per tick |
| `reconcile` | hand-driven | The fold above `join`ed with a replayed holdings stream into a `Reconciler` fold; mismatches and the re-base printed at the instants they happen |
| `latch_and_cap` | hand-driven | A `Switch` folded over the book's reading, an operator `clear` stream refused while a breach stands; `Capped` around `SimVenue` ending the run on the first over-cap place |
| `order_edge` | constructors and `validate` | **Stays off-graph.** It is vocabulary (`Order` constructors, `ExecId` capacity, the inert default). Its README states the exception |

Plus one new example, `strategy_loop/` (target `execution_strategy_loop`),
listed first in the group README: a toy quoter emitting `Desired`s off the
touch, `OmsOps`, `Capped(SimVenue)`, fills folded into a `Book`, a
`Reconciler` and a `Switch` on top, the latch feeding `cancel_all` back into
the OMS. One graph, the whole layer, the thing a venue integration copies.

Two conventions, both already in the root `CLAUDE.md`, that these rewrites
must honour:

- **Print as the run goes** — `print()`, `inspect(..)`, `for_each(..)`.
  Never `accumulate()` and `println!` afterwards.
- **A README's output is real** — run the target, paste what it prints.

## Shared wiring

Seven examples want the same loop. Rather than each rebuilding it, promote
the private `Script` / `closed_loop` from `tests/execution_fix_venue.rs`
into `testing::Scripted<I>` behind `execution-testing`: replayed rows for
touches, desireds, cancel-alls and trading states; `wire(&g)` returns the
streams (requests, reports, session) so an example can hang its own
printing and folding on them before `g.build()`. The integration test moves
onto it in the same PR so there is one copy. `order_edge` needs none of it;
`position_book` needs only a replayed fill stream.

## Sequencing

Three PRs, each green on the pre-commit checklist and
`scripts/check-example-docs.sh`:

1. **`testing::Scripted` + the four OMS examples** — `oms_quote`,
   `message_ratio`, `replace_chain`, `exchange_day`. The `CLAUDE.md` rule
   lands here.
2. **The three fold examples** — `position_book`, `reconcile`,
   `latch_and_cap`, plus the `order_edge` README note.
3. **`strategy_loop`** and the group README reorder.

## What this does not do

- Does not touch a unit test or `tests/execution_fix_venue.rs`'s assertions.
- Does not add position / reconcile / kill-switch nodes. `fold` is enough
  for an example; if the `strategy_loop` wiring shows a fold is awkward
  (the reconciler needs the book *and* holdings in a stated order within an
  instant), that is the finding that justifies a node, filed as its own
  issue.
- Does not change what any example demonstrates — the same behaviours, now
  observed at instants instead of narrated.
