# Execution layer examples: from hand-driven calls to graphs

**Status:** done — all three PRs. What remains is the follow-up this surfaced: library nodes for the position fold, reconciliation and the kill switch. Scope is `examples/adapters/execution/` only;
the unit tests stay as they are.

## The problem

All eight execution examples are off-graph. Not one constructs a
`GraphBuilder`; each holds an `Oms`, a `Book`, a `Reconciler` or a `Switch`
in `main`, advances a hand-rolled `at(ms)` clock in a `for` loop, and calls
`diff` / `apply` / `reconcile` / `record` by hand. That is the shape
`execution/CLAUDE.md` says a caller must not use ("a caller must not hold an
`Oms` in a `RefCell` and call it by hand from a graph … that is how every
caller came to re-derive the order"), so the examples teach the wrong thing
to the one audience that copies them. None of their wiring could be pointed
at a live venue, which the examples rule in the root `CLAUDE.md` calls the
anti-pattern. And they read like unit tests: a sequence of asserts with
`println!` in place of `assert_eq!`.

The graph API to do it right already exists: `OmsOps`, `AlgoOps` and
`FixOps` for the three stateful nodes; `testing::SimVenue` as a `Venue`
behind one `GraphBuilder::feedback` cut; `ceiling::Capped` wrapping any
venue; and `StreamOps::fold` for the three pure types that have no node of
their own (`Book`, `Reconciler`, `Switch` are all `Clone`, which is all
`fold` asks). `tests/execution_fix_venue.rs:449-483` (`closed_loop`) shows
the loop wired.

## The rule

> **Every execution example wires a graph and runs it under
> `RunMode::HistoricalFrom`, printing as the run goes.** The one exception
> is an example whose subject is vocabulary rather than behaviour, and its
> README says so.

It goes into `execution/CLAUDE.md` under *Tests* alongside the existing
"each with a README whose output is real".

## What each example becomes

Target names do not change; directory layout and the `adapters/` README
house style stay as they are. Every README's output is regenerated by
running the example, and stays stable because every run is historical.
Inputs that today are hand-stepped in a loop become replayed rows
(`g.replay_results(..)` at engine instants), the way `closed_loop` does it.

| Example | Today | Becomes |
|---|---|---|
| `oms_quote` | `Oms::diff` by hand, nine calls | A replayed decision stream into `OmsOps`; `SimVenue` behind the cut answers the requests; `print()` on requests and reports. Shows what the docs promise: one in flight per slot, the amend on a moved touch, withdrawal by decision and by age, the budget deferring |
| `message_ratio` | hand-driven | Same loop with `Config::ratio`; the held amend is visible as the instant it goes out |
| `replace_chain` | hand-driven `ReplaceChain` | `FixOps` on the graph in front of `SimVenue`, the renamed order and the fill on it printed as reports |
| `exchange_day` | hand-driven | A replayed `TradingState` stream driving `OmsOps` through the session: open, halt, close expiring day orders, re-open re-quoting |
| `position_book` | `Book::apply` by hand | An example-local `BookOp` (fills, then cashflows, into a `Book`), with a marks stream joined to print the valuation per mark |
| `reconcile` | hand-driven | An example-local `ReconcileOp` (fills, holdings, a sweep) holding the `Fold` and the `Reconciler`; mismatches and the re-base printed at the instants they happen |
| `latch_and_cap` | hand-driven | An example-local `SwitchOp` (readings, then an operator `clear`) holding the `Switch`, restarted from its `Snapshot` in a second graph; `Capped` around a venue ending the run on the first over-cap place |
| `order_edge` | constructors and `validate` | **Stays off-graph.** It is vocabulary (`Order` constructors, `ExecId` capacity, the inert default). Its README states the exception |

Plus one new example, `strategy_loop/` (target `execution_strategy_loop`),
listed first in the group README: a toy quoter emitting `Desired`s off the
touch, `OmsOps`, `Capped(SimVenue)`, fills folded into a `Book`, a
`Reconciler` and a `Switch` on top, the latch feeding `cancel_all` back into
the OMS. One graph, the whole layer, the thing a venue integration copies.

Two conventions, both already in the root `CLAUDE.md`, that these rewrites
must honour:

- **Print as the run goes** — `print()`, `inspect(..)`, `for_each(..)`.
  Never `accumulate()` and `println!` afterwards.
- **A README's output is real** — run the target, paste what it prints.

## Shared wiring — considered, and not done

The first draft promoted the private `Script` / `closed_loop` from
`tests/execution_fix_venue.rs` into a `testing::Scripted` so that seven
examples and the test shared one copy. PR 1 dropped it: the loop — the
replayed rows, `wire_oms(..).sweep(..).build()`, the one feedback cut, the
venue's `wire` — is about fifteen lines, and it is the thing each example
exists to show. Hidden in a harness, `oms_quote` would show nothing of
`OmsOps`. Each example wires its own loop and repeats the `replay` helper;
the integration test keeps its own.

One convention the four share, and the rest follow: the request wire is a
millisecond each way (`delay(WIRE)` on either side of the cut), so the
venue answers two milliseconds after a decision and every instant prints
on the millisecond grid. Without it the cut lands a nanosecond later and
the output has to explain a `+1ns`.

## Sequencing

Three PRs, each green on the pre-commit checklist and
`scripts/check-example-docs.sh`:

1. **The four OMS examples** — `oms_quote`, `message_ratio`,
   `replace_chain`, `exchange_day` — on `OmsOps` and `testing::SimVenue`,
   with the `CLAUDE.md` rule. **Done.** It surfaced one thing the
   hand-driven version hid: a resting bid priced through the ask fills as
   a taker and is wanted again the instant it fills, so the OMS places it
   again every round trip; `exchange_day`'s last step is now a
   `Desired::cross`, which is one-shot.
2. **The three fold examples** — `position_book`, `reconcile`,
   `latch_and_cap`, plus the `order_edge` README note. **Done**, and
   not on `fold`: `StreamOps::fold` takes one input, and each of the
   three needs two or more within one instant (fills then cashflows;
   fills, holdings, then a sweep; readings then a clear). Each example
   defines its own `#[op]` — twenty lines, the shape `oms/node.rs` takes —
   and a three-line fluent trait. That is the finding the plan said would
   justify a node: `position::node`, `reconcile::node` and
   `kill_switch::node` in the library are the follow-up, and the examples
   are their specification. One more rule surfaced: every stream type
   needs `Default`, and `Book` deliberately has none, so the book node
   emits `Option<Book<I>>`.
3. **`strategy_loop`** and the group README reorder. **Done.** One graph,
   one cut: the quoter reads the switch's stance passively and the halt is
   the OMS's `cancel_all`, both on the far side of the request cut, so
   closing the loop through the switch needs no second feedback edge. The
   desk op holds the `Book` and the `Reconciler` together, because the
   reconciler's `Fold` is the book — a second argument for one library node
   over the pair rather than two.

## What this does not do

- Does not touch a unit test or `tests/execution_fix_venue.rs`'s assertions.
- Does not add position / reconcile / kill-switch nodes to the library.
  PR 2 showed `fold` is not enough (see *Sequencing*): the three examples
  carry example-local ops, and library nodes are the follow-up to file.
- Keeps what most examples demonstrate, now observed at instants instead
  of narrated. Two changed: `exchange_day`'s last step became a
  `Desired::cross`, and `message_ratio`'s partial fill became a whole fill
  plus a fresh place.
