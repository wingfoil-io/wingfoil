# Wingfoil 10.0.0 — the latency capture API

> **Unreleased.** The page is written; the version number is provisional until
> the release is cut. Everything below has landed on `main`.

A focused release on one surface: `wingfoil::latency`. The mechanism is
unchanged — stamps are still a pass-through op writing one `u64`, the histogram
is still HDR-style and non-allocating, `Traced<T, L>` still crosses a process
boundary as plain `#[repr(C)]` bytes. What changed is what the API lets you
*say*, and what the report is willing to *claim*.

Two of the changes are breaking; both are one-line edits at the call site.

## The headline: a zero is no longer a measurement

`stamp` reads a per-cycle wall-clock snap, so two stages in the same engine
cycle share a timestamp and the hop between them cannot be measured. The
aggregator used to record that as a genuine **0 ns sample**. A pair of stages
that were never separately timed therefore reported

```
  produce -> publish              120            0            0            0            0            0
```

which is indistinguishable from a hop measured at sub-nanosecond cost — and
three of the four rows in this project's own `showcase/latency` report looked
exactly like that.

Every observation is now classified, and one that yields no measurement is
**tallied rather than recorded**:

| outcome | tally | meaning |
|---|---|---|
| `cur > prev` | `count` | a real measurement |
| `cur == prev` | `same_instant` | both stages in one engine cycle — stamp precisely |
| `cur < prev` | `backwards` | the clocks disagree; the numbers are not comparable |
| either stamp is 0 | `unstamped` | this hop is not instrumented |

The report prints dashes and the reason instead of numbers:

```
  produce -> publish                0            -            -            -            -            -            -  (100 same-cycle)
```

`backwards` was previously a silent `continue`, which is the more dangerous of
the two: the surviving `count` looked like a complete measurement. Turning it on
in `showcase/latency` immediately showed 35 of 100 cross-process observations
being rejected under the cycle clock — always true, never visible.

## `Stamping`: one argument instead of a method per combination

`stamp` / `stamp_precise` / `stamp_if` / `stamp_precise_if` (times two for the
burst-shaped twins) could not express *"precise or not, decided at runtime"*,
which is what a config flag is. The only way to write it was to pair two `_if`
calls with opposite polarities:

```rust
// Before — two nodes, and a dropped `!` double-stamps the stage, silently.
.stamp_each_if::<ws_recv>(!precise)
.stamp_precise_each_if::<ws_recv>(precise)

// After.
.stamp_each_as::<ws_recv>(Stamping::precise_if(precise))
```

`Stamping` is `Off` / `Cycle` / `Precise`, with `new(enabled, precise)`,
`precise_if` and `on_if` constructors for the shapes a config actually has. The
named stamps remain as the shorthands they are. `showcase/trading_e2e` went from
eighteen stamp calls to nine.

## `stamp_all`: N stages, one node

Every stamp op clones its input to write 8 bytes — each node owns its output
slot, so the clone is the engine's model. On a burst-shaped stream that clone is
a `Vec` allocation, which means instrumentation allocating on the path it
measures.

`stamp_all::<(A, B)>(mode)` (and `stamp_each_all`) writes a whole tuple of
stages from one op. It is not an approximation: under `Precise` each stage still
takes its own clock read, and on a burst each read is applied to every value in
the group. Fusing `N` adjacent stamps saves `N - 1` clones and changes no
number. Tuples of 1 to 8 stages are supported via the new `StageSet` trait.

## `LatencyHandle`, and latency as a stream

`latency_report` returned `Rc<RefCell<LatencyStats<L>>>`. Three consequences,
all now addressed:

- **No reset.** Statistics were cumulative for the life of the run, so one
  outlier pinned the p99 forever — a gauge fed from that records the worst
  second the process ever had, not the state it is in. `LatencyHandle` has
  `reset` and `take` (snapshot-then-reset).
- **Read-out by raw index.** Consumers reproduced the `stages[1..N]` convention
  themselves. `hops()`, `total()` and `snapshot()` return labelled, `Copy`
  `HopStats` instead.
- **Only a teardown `print`.** `windows(&g, period)` emits a
  `Stream<LatencySnapshot>`, one per period, so latency drives gauges, alerts
  and downstream ops. `showcase/trading_e2e`'s 25-line Prometheus helper became
  a loop over `hops()`.

## The end-to-end total

`stages[0]` was allocated and never written — stage 0 has no predecessor. It now
carries the **end-to-end** delta, first declared stage to last, printed as the
report's final row and exposed as `LatencyStats::total()`.

This cannot be recovered by summing the per-hop rows: a hop that skipped an
observation is exactly the hop that would make the sum wrong. Every consumer
that wanted the number was computing it by hand.

## Smaller changes

- **`p99.9` in the report**, and a **self-sizing label column** — long stage
  names pushed the numeric columns out of alignment.
- **`ReportOutput`** replaces `print_on_teardown: bool`: `Silent`, `Stdout` or
  `Log`. The report was hard-wired to stdout, which a process reserving stdout
  for structured output cannot use.
- **`StageStats` is no longer `Copy`.** It is dominated by its histogram — 7.7 KB
  when the ceiling was `2^34` ns — so every by-value use was a silent
  multi-kilobyte `memcpy`. The octave ceiling is now `2^30` ns (~1.07 s), which
  is still far past any per-hop latency worth a percentile and takes the struct
  to 6.7 KB. `HopStats` is the small `Copy` read-out.
- **`latency_stages!` needs no imports.** The expansion names
  `::wingfoil::latency::Latency` / `Stage` in full and routes serde through
  wingfoil's own re-export, so a call site no longer imports two traits it never
  names or depends on serde directly. wingfoil's own examples carried a comment
  apologising for the old requirement.

## Breaking changes

Two, both mechanical:

| Before | After |
|---|---|
| `stream.latency_report(true)` | `stream.latency_report(ReportOutput::Stdout)` (`false` → `ReportOutput::Silent`) |
| `let (sink, stats) = …; stats.borrow().stages[i]` | `let (sink, latency) = …; latency.hops()[i - 1]` (`.borrow()` still works) |

`LatencyStats::stages` is still `pub` and still indexable; only `stages[0]`
changed meaning, from "permanently empty" to "the end-to-end total".

In Python, `latency_report(..., print_on_teardown=True|False)` becomes
`latency_report(..., output="stdout"|"log"|"silent")`, and `stamp_as` /
`stamp_all` / `LatencyStats.total` / `.hops()` / `.reset()` are new.

## What did not change

Stamps are still `Activation::NONE` pass-throughs. The four named stamps still
reach all three `nitro!` expansions (`stamp_as` / `stamp_all` are fluent-only:
both pick a node from a runtime value, and a `nitro!` graph's topology is fixed
at expansion). `latency_report` is still interpreted-only, still for the
structural reason recorded as deviation **C7**. The wire format of a
`latency_stages!` record — N little-endian `u64`s — is untouched, so a 10.0
process and a 9.0 process still understand each other's `Traced` payloads.
